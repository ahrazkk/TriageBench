# Design note: the MVP cut (M0 to M6)

Written 2026-11-07, before the first live eval. This note covers what the MVP builds, how each
part is tested, which number each part should move, and **every deviation from docs/PLAN.md**
with its reason.

## What we're building

```
collector (GitHub REST) → redacted log + failure-time snapshots + labeller hints
                        → data/cases.jsonl (+ data/raw/<job_id>/)
labels (AI-drafted → human-verified) → data/labels.jsonl
                        ↓
tools/impl.py (7 read-only tools) ──► mcp_server.py (same tools over MCP)
                        ↓
B0 regex · B1 single call · B2 agent · B3 agent + pgvector hybrid retrieval
                        ↓
evals/ (metrics, Wilson/bootstrap CIs, McNemar) → results/*.json → docs/RESULTS.md
```

| Part | Tested by | Number it moves |
|---|---|---|
| Collector + redaction | respx client tests; redaction unit test | cases collected; redactions per case |
| Reducer | Hypothesis properties (budget, order, last line) | tokens per triage; accuracy (tail vs hybrid) |
| Verifier | exact-quote / edited-quote / wrong-line tests + Hypothesis | evidence validity |
| Agent loop | FakeLLM scripts: normal, unknown tool, tool error, budgets, repair | B2 vs B1 accuracy, steps, cost |
| Retrieval | pgvector tests: finds the right kb case, **no leakage**, HNSW = exact | recall@5; B3 vs B2 |
| MCP server | contract test: every tool over MCP == direct call | latency overhead per call |
| Harness | known-value stats tests (Wilson 80/100 = 71.1–86.7%, McNemar b=2,c=9 → 0.065, RRF) | — |

## Deviations from the plan (and why)

1. **Model: Claude Haiku 5.5, not Gemini.** Ahraz has Claude API credit and chose Haiku 5.5
   ($0.10 / $0.50 per 1M tokens, checked 2026-11-07) for cost. The `LLMClient` interface keeps
   the provider swappable; a bigger model (Sonnet 5.5) is a planned ablation. Effort is set
   explicitly to `medium` (Haiku 5.5's default) so it's recorded with every result. Thinking is
   adaptive (Haiku 5.5 doesn't allow turning it off at all efforts), and `temperature` isn't
   sent (the current API rejects sampling parameters).
2. **PostgreSQL natively in WSL (apt), not Docker.** There's no Docker on this machine. Ubuntu
   24.04's `postgresql-16-pgvector` is pgvector **0.6.0**: HNSW yes, iterative index scans no
   (0.8+). Our kb is small and filtered by `split`, so a filtered HNSW scan returning fewer rows
   than `LIMIT` is possible in principle; the `test_hnsw_matches_exact_search` test checks it.
   CI uses the `pgvector/pgvector:pg17` image (0.8.x).
3. **Repo on the Windows drive, venv in WSL**, same as MiniServe (so the desktop app and editors
   see the files). Raw logs live in `data/raw/` (git-ignored).
4. **The dataset lives in JSONL, the database holds only the search index.** `data/cases.jsonl`
   and `data/labels.jsonl` are diffable and reviewable in git; `triagebench index` rebuilds the
   `chunks` table from them. One less thing to keep in sync, and CI needs no data migration.
5. **The agent only sees what existed when the job failed.** Run history is fetched with
   `created < failure time`. The re-run outcome, the next green commit and its changed files are
   **labeller hints only**. The plan's B0 rule "run attempt 2 passed → flaky" would leak the
   label (the label is largely derived from that signal), so B0 doesn't get it either. This makes
   axis B genuinely hard, which is the honest version of the task: a triage bot runs before
   anyone presses "re-run".
6. **Evidence check = whole line or a verbatim substring of ≥ 15 characters.** Excerpts cut lines
   at 400 characters, so the model may only see the start of a long line. Paraphrases and wrong
   line numbers still fail.
7. **MVP labels are AI-drafted, then human-verified.** Claude (Opus, via Claude Code subagents)
   drafts each label from a "label pack" that includes the future hints the systems never see.
   Drafts are stored `ai_drafted: true, verified: false`; Ahraz reviews each one with
   `triagebench review`. Until then every number is **preliminary** and says so. Known risk: the
   drafter and the agent are both Claude models, which could share blind spots. Human review is
   the mitigation; it's also a good interview talking point.
8. **Splits are kb / dev only for now**, time-based per repo (oldest 50% → kb). `test` is frozen
   in M7 when the dataset reaches 100–150 cases.
9. **MCP Python SDK 2.3** (newer than the plan's v2 notes): `MCPServer`, a single `Client`
   (which can connect to a server object in memory, which is what the contract test uses), and
   tools annotated `read_only_hint=True`.

## What "done" looks like for the MVP

- B0, B1, B2, B3 run end to end on the dev split; results files saved; RESULTS.md has the table
  with 95% intervals, the paired McNemar tests and the label status.
- The MCP server works from Claude Code.
- CI: ruff, mypy --strict, pytest (with a Postgres service for the retrieval/leakage tests).

## Iteration 1: agent v2 (2026-11-08)

Driven by the v1 error analysis (docs/RESULTS.md):

- **Budget-aware loop** (`agent/loop.py`, prompt `agent_v2.md`): after each tool round the model
  sees `[budget: N model turns and about M input tokens left]`. The loop estimates the next
  request's size (this request + the reply + the new tool output); when this turn plus one more
  could overrun the budget, or it is the last turn, the turn is made final with
  `tool_choice: {"type": "none"}` and a "give your final answer now" note. Budget exhaustion
  becomes a low-confidence answer instead of a failure.
- **Retrieval as hints** (`prompts/retrieval_v2.md`): list a similar case only when its error
  clearly matches; never adopt its labels without this job's own evidence.
- **Versioning:** `TRIAGEBENCH_PROMPT_VERSION` (default `v2`) selects prompts and loop behaviour.
  v1 prompts are byte-identical to the measured ones, and `tool_choice` only enters the cassette
  key when set, so v1 replays exactly.
- **Repeats:** `triagebench eval --repeat k` puts `k` in the cassette key, so each repeat makes
  fresh model calls; `scripts/repeats.py` reports mean, range, flip rate and paired tests on
  per-case means.

Tests: FakeLLM tests for v1 hard budget failures (pinned to v1) and v2 behaviour (budget note,
tools off on the last turn, token budget forces an answer).

## Fix: PR diffs must stop at the tested commit (2026-11-08)

`change_summary` used `compare(pull_requests[0].base.sha, pull_requests[0].head.sha)`. Those
fields describe the PR *when the run object is fetched*, so the head can be later than the commit
CI tested, including the fix. That broke rule 5 above ("the agent only sees what existed when
the job failed"). Now: `compare(base, run["head_sha"])` (three-dot, so a moved base doesn't
matter), with the compared commits recorded in the snapshot (`compared`), and
`test_pr_diff_stops_at_the_tested_commit_not_the_current_pr_head` pins it. Found by an AI judge
during the model-disagreement review; 9 cases rebuilt with `scripts/fix_pr_diffs.py`.
